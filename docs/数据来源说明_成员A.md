# 数据来源说明（成员A · 第4周交付物）

> 撰写人：成员 A（项目负责人 + 数据采集工程师）
> 项目：宁波市二手房市场价格分析与可视化研究（方向 C）

## 一、项目背景

本项目研究宁波市二手房挂牌价格，需采集真实房源数据用于后续清洗、分析与可视化大屏。核心数据需求为：房源基础信息（小区、户型、面积、朝向、楼层）、价格信息（总价、单价）、区位信息（行政区），目标规模 1000 条以上。

## 二、数据源选择过程（为什么是贝壳，不是链家）

**最初选择链家（`nb.lianjia.com`）**，理由是房源字段齐全、页面结构规整、分页规律清晰，是课程项目常用数据源。

但实际采集时遇到严重反爬：

| 阶段 | 遇到的问题 |
|---|---|
| 链家列表页 | 第 2 页起返回「小怪兽」行为验证码，`requests`、`curl_cffi`（伪装 TLS）、Playwright 无头/有头、手动解验证码均无法通过 |
| 换 IP | 无效，验证码依然拒绝 |

经排查确认：链家/贝壳的反爬是**行为验证码**，能识别自动化浏览器的多种指纹，普通爬虫手段无法绕过。

**最终改用贝壳找房（`nb.ke.com`）**——它与链家同属贝壳系，房源数据相同，但反爬机制不同：贝壳列表页第 2 页起是「登录」拦截（而非验证码），通过真实浏览器登录即可绕过。

## 三、最终数据源

| 项目 | 说明 |
|---|---|
| 数据源 | 贝壳找房 · 宁波站 |
| 列表页地址 | `https://nb.ke.com/ershoufang/` |

| 采集时间 | 2026-11-25 |

## 四、采集方案

1. **真实浏览器接管**：用 Playwright 的 CDP 协议连接用户已登录的真实 Chrome 浏览器，浏览器指纹真实，不会被反爬识别。
2. **登录授权**：在真实浏览器中登录贝壳账号，通过第 2 页起的登录拦截。
3. **按行政区筛选采集**：利用贝壳的区域筛选 URL（如 `/ershoufang/yinzhouqu2/` = 鄞州区），逐行政区翻页采集，每条房源自动带上行政区字段，无需访问详情页（详情页有独立的 hip 验证码，无法自动访问）。
4. **合规采集**：翻页设置随机延时，不进行高频并发访问；数据仅供课程学习使用。

## 七、数据质量

经第 3 周数据质量检查（详见《数据质量检查记录》），结论为**数据质量优秀**：

- 仅「楼层」30 条缺失（2.51%，来源端未提供，非采集错误）；
- 房源链接、整行均无重复；
- 面积、户型格式零异常；
- **总价 ≈ 面积 × 单价 ÷ 10000，一致性偏差 0 条**，证明价格、面积采集完全正确；
- 异常值均为合理的高价房、大户型。
