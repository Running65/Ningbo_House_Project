## 排错案例（最终需 ≥3 个，每个写清楚）

### 案例 1：爬虫采集的「单价」字段多带「元/平」单位

- **问题现象**：运行 spider.py 采集后，raw_data.csv 里「单价(元/平)」字段值是 `16,064元/平`，而「总价(万)」是纯数字 `179`，两个价格字段格式不一致，单价无法直接做数值计算。
- **排查过程**：检查保存的网页 HTML，对比 unitPrice 和 totalPrice 的实际结构，发现单价的 `<span>` 标签文本自带单位（`<span>15,671元/平</span>`），而总价的单位「万」在 span 标签外面（`<span>179</span>万`）。
- **根本原因**：网页里两个价格字段的 HTML 结构不一致——单价的单位写在 span 标签内、总价的单位写在 span 标签外；代码直接 `get_text` 提取 span 文本，导致单价多带了单位。
- **修复方案**：新增 `clean_price()` 函数，用正则 `re.sub(r"[^\d.,]", "", text)` 只保留数字、逗号和小数点，统一清理两个价格字段。
- **经验总结**：解析网页字段不能想当然假设标签结构一致，要实际查看每个字段的 HTML；数值字段最好用正则或 data-* 属性统一提取纯数值。

### 案例 2：链家/贝壳反爬对抗——最终用真实浏览器（CDP）解决

- **问题现象**：爬虫只能采到列表第 1 页 30 条，第 2 页起链家返回验证码页、贝壳跳转登录页；手动解验证码也一直提示「小怪兽捣乱」，换 IP 也没用。
- **排查过程**：依次尝试了 `requests` → `curl_cffi`（伪装 TLS 指纹）→ Playwright 无头（被 403）→ Playwright 有头（第 2 页仍验证码）→ 手动解验证码（「小怪兽捣乱」不过）→ 换手机热点 IP（还是不行）→ 加 stealth 隐藏 `navigator.webdriver`（还是被拦）。
- **根本原因**：链家/贝壳的反爬是行为验证码，能识别自动化浏览器的多种指纹（TLS 指纹、`navigator.webdriver`、操作节奏等），普通伪装手段都瞒不过它。
- **修复方案**：改用 **Playwright CDP 接管用户真实 Chrome**（真实浏览器指纹 + 登录会话），遇到人机验证时人工完成一次，最终成功采集 **1320 条**房源。
- **经验总结**：对抗强反爬，与其层层伪装自动化浏览器，不如直接用真实浏览器（CDP 接管）——指纹真实才最可靠。这也是「换 IP 没用、换浏览器有用」的根本原因。

### 案例 3：中文输出乱码——Windows 控制台 GBK 与 UTF-8 冲突

- **问题现象**：C++ 程序输出中文（如「萧逸最帅」）时，终端显示成一堆乱码，看起来像程序出错。
- **排查过程**：检查源文件编码发现是正常的 UTF-8，g++ 编译也成功，但控制台里中文就是乱。用 `xxd` 查看程序输出字节，确认输出的是正确的 UTF-8（`e890a7...`），问题出在「显示」环节。
- **根本原因**：Windows 控制台默认代码页是 GBK(936)，而程序输出的是 UTF-8 字节，控制台用 GBK 去解读 UTF-8，于是乱码。
- **修复方案**：在编译运行命令前加 `chcp 65001`，把控制台代码页切换到 UTF-8；并把它固化进 VS Code 的编译任务配置里。
- **经验总结**：中文乱码先分清是「文件/程序编码问题」还是「终端显示编码问题」；Windows 上输出 UTF-8 前记得 `chcp 65001`。

## 提示：什么算「排错案例」

只要是「AI 生成的代码/方案出了问题 → 你发现 → 查原因 → 修好」的过程，都算。比如：

- 爬虫字段解析错误（如单价多带「元/平」单位）
- 反爬对抗（验证码、登录拦截）
- 中文乱码 / 编码问题
- 翻页逻辑不对
- 数据缺失、重复
- Git 冲突解决

每个案例按上面的「现象 → 排查 → 原因 → 修复 → 总结」五步写即可。
